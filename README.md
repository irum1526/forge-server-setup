# Forge服务器搭建：Java版本、内存分配、MOD不加载一次讲清，新手也能开起稳定MOD服

搜「Forge服务器搭建」的人，卡住的地方往往出奇地一致：`run.bat` 双击一下，黑窗口闪一下就消失了；或者服务端明明启动了，朋友那边一直「连接超时」；再或者进去了，玩十分钟 TPS 掉到个位数，控制台刷满 `Can't keep up`。

Forge 本身没那么多坑，出问题的是它周围那几件事——Java 版本、内存分配、端口、mod 一致性。把这四样定死，剩下的就是点几下按钮的工作。

下面按真实开服顺序走一遍：先确认你需要哪种服务端，再排掉最常见的五类报错，然后看三条搭建路线怎么选，最后是用面板一键开 Forge 服的具体操作和当前价格。

## 先确认：你要的是 Forge，还是别的服务端

很多人其实不需要 Forge。选服务端之前先想清楚一件事：你要装 mod，还是装插件？

| 服务端 | 能装什么 | 什么时候选它 |
| --- | --- | --- |
| 官方原版 | 都不能 | 纯原版生存 |
| Paper / Purpur | 插件 | 加插件、追求性能，1.20+ 的主流选择 |
| Forge | mod | 玩 mod、跑整合包，模组生态最老最全 |
| NeoForge | mod | 1.20.2 之后从 Forge 分出来的分支，新版本适配更快 |
| Fabric | mod | 轻量 mod 场景，更新跟得快 |

一个常被忽略的细节：插件端和 mod 端不通用。Paper 上装的 `.jar` 插件放到 Forge 的 `mods` 文件夹里不会生效，反过来也一样。

另外，如果你打算跑的是某个现成整合包（FTB、ATM 这类），先去看整合包的要求，再倒推服务端类型和游戏版本——不要反过来先搭好服务端再去找能用的整合包，那样大概率对不上。

## 五个最容易卡住的地方

### Java 版本和游戏版本必须对上

这是新手第一个卡点，装错了服务端连启动都做不到，报错通常是 `Unsupported class version`。

大致对应关系是：

- 1.16 及以下 → Java 8
- 1.17 ～ 1.20.4 → Java 17
- 1.20.5 及以上 → Java 21

不同教程对 1.17～1.20.x 这段的划分会有一点出入（有的把 1.17.1 划给 Java 16），不用纠结，看服务端文件夹里那个启动脚本写的是什么，照它来就行。整合包自带的 `startserver.sh` / `run.bat` 一般已经指定好了版本。

Java 装完之后，启动脚本里找不到 java 命令的情况也很常见，需要把 `java` 换成 java.exe 的完整路径。

### 内存给多少，取决于 mod 数量

原版服 2G 能跑，Forge 服 2G 会直接 OOM。模组吃内存的量级和原版完全不是一个概念：

- 几十个 mod：8G 起步
- 100 ～ 200 个 mod：12G 左右
- 200 个以上：16G 以上

分配时别把机器内存全给 Java。建议设成总内存的 60% ～ 70%，剩下的留给系统，4G 的机器给 3G，8G 的机器给 6G。给满了系统没内存可用，反而更容易崩。

分配方式就是改 `user_jvm_args.txt`，在最后加一行：


-Xms6G -Xmx6G


顺便加一句 `-XX:+UseG1GC`。模组服堆内存大、对象又多，G1 的停顿表现比默认收集器稳定。

### 25565 端口和防火墙

Minecraft Java 版走 TCP 25565，基岩版走 UDP 19132，两者不能互通。

如果用云服务器，除了系统里的防火墙，还要在机房那边放通端口：轻量服务器一般在实例详情的「防火墙」页签加规则，云服务器在安全组的入站规则里加。只改一边，外面照样连不上。

如果买的是 NAT 机型（没有独立公网 IP），还需要在控制器里做端口映射，把内网的 25565 映射到公网端口，玩家连接时用「IP:映射端口」。

### eula.txt 不改，服务端根本不启动

第一次启动一定会停在这里。打开服务端根目录的 `eula.txt`，把 `eula=false` 改成 `eula=true`，保存，重新启动。这不是可选项，是 Mojang 的强制要求。

### mod、服务端、客户端三边版本要一致

这条是 Forge 服最耗时间的部分。三种情况最常见：

1. **mod 版本和游戏版本不匹配**——给 1.20.1 用的 mod 塞进 1.19.2 的服务端

2. **缺前置依赖**——很多 mod 依赖另外几个库，光装本体不装前置会直接崩

3. **服务端能跑，客户端进不来**——玩家那边的整合包版本、mod 列表必须和服务端完全对应，少一个都可能连接失败

排查方法笨但有效：清空 `mods` 文件夹，每次加 5 个，加完重启一次，哪组崩了就在那 5 个里面找。崩服的服务端根目录会有 `crash-reports` 文件，里面直接写了是哪个 mod 出的问题。

还有一种不报错但会卡住的情况：某些 mod 在开服时会联网校验版本（暮色森林这类会去访问 GitHub），国内机房访问不畅时，开服流程会停在那一行不动，服务端进程还在，但一直不进入完成状态。

## 三条搭建路线：本地、VPS 自建、面板服

| 路线 | 成本 | 适合谁 | 主要麻烦 |
| --- | --- | --- | --- |
| 本机 + 内网穿透 | 最低 | 2～3 个朋友临时联机 | 电脑不能关、穿透带宽小、存档在本机 |
| 云服务器 VPS 自建 | 中等 | 想同时跑多个服、要装其他程序 | 全流程手动，系统、Java、服务端都要自己配 |
| 面板服（MCSManager 之类） | 按配置走 | 新手、只想开一个 MC 服 | 只能单端，扩展性差一些 |

区别说白了就一句：VPS 给的是整台机器，你想装什么都行，但配置环境也得你自己来；面板服给的是一个已经装好 Java、指向 MC 的容器，网页点几下就能开服，代价是扩展性有限。

如果目标只是「和朋友稳定联机一个 Forge 整合包」，面板服省下的时间比省下的钱更值。

2. **进入「游戏云 → 购买游戏云」**。服务器类型选雨云面板。

3. **游戏类型选 Minecraft Java 版，服务端类型选 Forge**。面板目前支持的服务端里已经包含 Forge 和 NeoForge，另外还有官方原版、Paper、Purpur、Fabric、Mohist、CatServer 等，版本覆盖 1.8.8 到最新。如果你要开的是带 config、带完整模组的整合包，服务端类型改选「纯 Java 环境」（面板提供 JDK 8/11/17/21），然后把整合包的服务端压缩包上传上去。

4. **选机型和配置**。面板目前可选的机型包括 i9 14900KS 和 Platinum 8259CL，历史机型还有 Ryzen 7950X、5900X、Gold 6146、E5 2666v3 等。**MC 服务端的主逻辑跑在单线程上，核心数多但主频低，实际不如核心少而主频高**。1.17 以上的版本对单核性能要求更明显，预算允许就上 14900K 这类高主频机型。配置建议 4 核 8G 起，跑 200+ mod 的整合包别低于这个数。

5. **选计费模式**，固定或者动态，下面单独说。

6. **购买后进入管理页**，点击面板地址，用面板提供的账号密码登录，同时记下页面上显示的「对外地址:端口」，这就是玩家要填的服务器地址。

7. **上传 mod 并配置**。在文件管理里新建 `mods` 文件夹，把 mod 的 `.jar` 拖进去；在「服务端配置文件」里改端口、正版验证、视距这些参数；改完重启服务端。启动脚本里别忘了分配内存。

8. **看控制台输出**。出现 `Done (xx.xxxs)! For help, type "help"` 就是开好了。

9. **进服测试**。自己先用和服务端完全相同的整合包进一次，确认版本没问题，再把地址发给朋友。

## 动态计费和固定计费，怎么选

这是雨云游戏云里最值得花两分钟搞清楚的东西，因为能直接省钱。

- **固定计费**：固定月租，不额外收费。适合服务端长期开着的情况。
- **动态计费**：低价月租 + 按 CPU 实际消耗额外结算。每天定时用余额结算上一天的 CPU 消耗，闲时几乎不产生费用，忙时按量算。
- **按天计费**：面板服专供，每天定时用余额结算下一天的日租。

判断标准很简单:一台每天只有晚上三四个人在线的 Forge 服，选动态计费；一台全天在线、CPU 常年在 50% 以上的社区服，选固定计费。动态计费需要账户里留有余额，这点别忘。

## 优惠、试用和退款：先花小钱试错

开服这件事最怕的是买了不合适再折腾退款，所以试错成本值得单独看一眼：

- **首月 5 折**：通过优惠链接注册并绑定微信后可以领取
- **年付 7 折**：长期开服直接年付，这个折扣是官方常态活动，不需要等大促
- **低价试用**：云服务器和游戏云支持 1 元试用 1 天（部分较贵的机型试用价会高一点），面板服一般是 2 元试用 1 天
- **7 天无理由退款**：每个账号限 3 次
- **免费面板服**：积分商城里有免费的面板服可以兑换，库存有限、先到先得

对新手来说最合理的路径是：先用试用价开一天，把 Forge 服务端和整合包跑起来，确认内存够用、mod 不冲突，再决定买哪个档位、买多久。

## server.properties 里值得改的几行

Forge 服和原版服在配置文件上的差别，主要在这几项：


server-port=25565
online-mode=true          # 离线客户端联机时改成 false
allow-flight=true         # 装了带飞行坐骑或装备的 mod 必须打开
max-tick-time=180000      # 模组加载慢，超时时间要放宽，也可以设 -1
view-distance=10          # 人多或机器弱时下调，先降到 8
simulation-distance=6


`allow-flight` 这项特别容易漏。模组服里有飞行类物品和坐骑，保持默认的 `false`，玩家一飞起来就会被判定成外挂直接踢出，而且提示信息不会告诉你是这个原因。

`online-mode` 建议保持 `true`。改成 `false` 会让任何名字的人都能顶替别人身份进服，如果确实需要离线模式，记得装上登录插件。

视距是性能成本最高的一项。2～3 人玩可以设 16/10，5、6 人设 10/6，人再多或者机器吃紧就降到 8/4。

## 常见报错对照

| 现象 | 大概率原因 |
| --- | --- |
| 双击启动脚本，窗口一闪就关 | Java 没装、版本不对，或脚本里的 java 路径不对 |
| `Unsupported class version` | Java 版本低于游戏版本要求 |
| `You need to agree to the EULA` | `eula.txt` 里还是 false |
| 启动了但玩家连接超时 | 端口没放通（系统防火墙 + 机房安全组 / NAT 映射） |
| 提示 mod 版本问题 | mod 与游戏版本不匹配，或缺前置依赖 |
| 玩家被踢，提示飞行异常 | `allow-flight` 没打开 |
| 控制台刷 `Can't keep up` | 内存或单核性能不足，降视距、加内存或换高主频机型 |
| 开服卡在某一行不动 | 某个 mod 在联网校验版本，网络访问不畅 |

## 最后

Forge 服搭建的门槛没有传说中那么高，真正需要判断的只有三件事：Java 版本对上游戏版本、内存给到与 mod 数量匹配的量、端口两边都放通。剩下的失败案例，九成都出在 mod 版本一致性上，而这个只能靠一组一组试出来。

如果你不想在系统环境上花时间，面板服一键开 Forge 是更省事的路径；如果打算长期维护一个社区服、还要顺带跑别的服务，那就选 VPS，多出来的配置工作换来的是完整的控制权。先花几块钱试一天，把整合包和内存跑通，比看十篇教程都管用。
